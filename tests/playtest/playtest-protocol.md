# 黑白棋 · 真人试玩执行手册

> 这不是给工程师看的文档，是给**组织试玩的人（主理人）**看的。
> 目标：一小时内，让 1–2 个没接触过这个项目的人真刀真枪玩一局，然后把他们卡住的地方记下来。
> 本轮不需要写任何代码，只需要**照着下面的话术发出去**，然后记录。

---

## ⚠️ 当前执行状态（2026-10-12 · Phase 6 结案时定稿）

### 结论先说

**真人试玩没有执行。** 原因是**被试不可得**——约不到一个"没接触过这个项目的人"。
本手册全文因此**原样保留**，它不是废纸，是**将来找到真人时可直接复用的资产**：话术、时间盒、
勾选标准、观察点都已就绪，届时不需要重写，只需按第 2 节发出去即可。

判定与详证见 `phase6-verdict.md`。

### 已由主理人 n=1 实测覆盖的部分

主理人本人与 AI 对弈并判断正常。这一轮覆盖了本手册的 **T1 / T3 / T4**（AI 单机链路），
对应 `smoke-checklist.md` 的冒烟项编号：

| 冒烟项 | 内容 | 覆盖方式 |
|---|---|---|
| A1 / A2 | 首页入口与人机对战入口、难度选择 | 主理人 n=1 走过 AI 入口 |

| E1 | AI 思考时**界面不冻结** | 主理人 n=1 |
| E2 | AI 思考有可见状态反馈 | 主理人 n=1 + `[UNIT]` 断言「AI 思考中…」 |
| E3 | AI 落子后**立刻**交回回合，无空窗 | 主理人 n=1 |

### 仍未由真人覆盖的部分

**T2（联机全流程 + 断线刷新）没有任何真人验证。** 主理人本轮只玩了 AI，没有开过联机对局。

- 机器侧由本轮新增的 `e2e/reconnect.spec.ts` 承接（断线重连、刷新后状态恢复）。
- **注意**：自动化只能证明"数据一致"，证明不了"人看着不难受"。T2 的体验层仍需人工过一遍。

### 如果将来找到真人，从哪里开始跑？

**从 T2 开始，不是从 T1 开始。** 理由：

1. T2 是唯一有**零容忍项**（刷新后身份错乱 / 双方回合永久冲突）的 Task，风险最高而当前证据最薄。
2. T1 / T3 / T4 已有 n=1 + 单元测试双重覆盖，边际信息量低；重跑它们是浪费被试注意力。
3. 真人愿意投入的注意力有限，**先花在高风险路径上**。

配套可直接使用的记录表见 `observation-sheet.md`，逐项覆盖方对照见 `smoke-checklist.md`。

## 0. 时间盒（先看这个）

| 内容 | 时长 |
|---|---|
| 8×8 黑白棋单局（两个新手、都慢慢想） | 8–12 分钟 |
| 8×8 黑白棋单局（熟手 / 对 AI） | 4–6 分钟 |
| Task 1 首次上手 | 3 分钟 |
| Task 2 联机全流程 + 断线刷新 | 10 分钟 |
| Task 3 AI 难度体感 | 8 分钟（只打简单 + 困难各一局） |
| Task 4 完整对局到终局 | 10 分钟 |
| **四个 Task 合计** | **约 30 分钟**（含被试思考时间，建议总窗口留 45 分钟） |

一局大概 60 手，新手会更快放弃思考、按感觉点。**超过 15 分钟还没走完一局，就当作"节奏太慢"的观察结论记下来**，别硬等。

## 1. 前置准备

### 1.1 你需要什么

- **Node.js ≥ 22.22.2**（推荐 24 LTS），已 `npm install` 过（项目里 `node_modules` 已存在）。
- **两台设备或两个浏览器窗口**。同一个浏览器开两个普通窗口**不行**——localStorage 会串，两边会被认成同一个人。正确做法：
  - 方案 A（推荐，最省事）：一个**普通窗口** + 一个**无痕/隐私窗口**。
  - 方案 B：Chrome 一个**普通 profile** + 另一个 profile，或两台设备。
  - 方案 C：本地起服务后，用手机连同一局域网访问电脑 IP:5173（注意：手机端和电脑端必须都能访问后端；如果只用本地 mock API，手机端可能连不上，那就用方案 A/B）。
- 一个能截图/录屏的地方（手机拍照也行，验证报告里要附证据）。

### 1.2 起服务（本地，不需要连 EdgeOne）

```bash
cd F:/other/code/ai/othello-online
npm run dev
```

看到类似 `Local: http://localhost:5173/` 就成了。
**本地已经内置了一个内存版后端**（`server/mockApi.ts`），所以不需要配 KV、不需要连 EdgeOne 控制台。

> 如果你想测真实部署环境，就部署后用线上地址重复同样的步骤，并在记录表环境栏写"线上"。两种环境都测是有价值的——mock 快，线上才是真实延迟。

### 1.3 让被试知道什么（不要多说）

只说三句：

1. "这是一个网页版黑白棋，你能跟朋友联机下，也能跟电脑下。"
2. "过程中请把你想说的都说出来，别管我有没有在听。"
3. "玩完我会问你几个问题。"

**不要**告诉被试"提示默认在联机关閉、AI 局开着"——那属于我们要观察的点。

### 1.4 三种入口怎么进（发话术时用得上）

| 入口 | 怎么进 |
|---|---|
| 联机对战 | 首页 → 点「创建房间」→ 把 6 位房间码发给对方 → 对方首页输入房间码 → 点「加入」 |
| 人机对战 | 首页 → 点「人机对战」（或直接访问 `/ai`）→ 选难度 → 开始 |
| 练习/看提示 | 对局页有「显示落子提示」开关，联网默认关，AI 局默认开，可在页面上手动切换 |

## 2. 试玩脚本（4 个 Task）

> 每个 Task 都给三样东西：**给被试的原话（可直接复制）**、**要盯的行为点**、**可勾选的通过标准**。
> 勾选标准是"必须全过才算这个 Task 过关"，达不到就记成问题，**不要现场解释怎么操作**——你一解释，这个观察点就作废了。

### Task 1 · 首次进入：能不能立刻上手（可发现性）

**时间：3 分钟**

#### 给被试的话术（复制发给朋友）

> 你先自己玩 3 分钟，我不说话也不提示你。
> 规则你应该知道：黑棋先走，每次落子必须夹住对方的棋子，被夹住的就翻成自己的颜色。谁先落子谁先走。
> 落子、下子、看谁赢，随便你怎么点都行。
> 过程中如果你觉得"这怎么弄"或者"这啥意思"，直接说出来。

**观察者要做的事**：全程别说话。被试卡住超过 **20 秒**才小声问"你在想找哪个位置？"——记住卡了多久、卡在哪。

#### 要盯的行为点

1. 能不能自己找到「人机对战」入口（首页最显眼位置）
2. 能不能自己分清黑棋白棋、谁先走
3. 第一次落子有没有犹豫/试错——特别是**落子能不能夹住棋子**这条规则，有没有意识到
4. 落子后有没有意识到"我下的这一手把对方几颗子翻了"
5. 有没有去找提示开关、主题/暗色开关、音效开关
6. 主观感受：会不会觉得"这界面我得学一下"

#### 通过标准（勾选）

- [ ] 被试在 **60 秒内**自己点进「人机对战」并开了一局
- [ ] 没有问"我该点哪个格子"（规则是已知的，只需验证可发现性）
- [ ] 第一次落子**合法**（没有出现落下去但什么都不翻的情况，被试自己会"咦？"）
- [ ] 被试**自己说出**"哦，这颗翻了"这类反馈（说明翻转动画/结果被感知到）
- [ ] 至少主动发现了 2 个可用开关中的 1 个（提示 / 音效 / 暗色）
- [ ] 观察者全程没有给出任何操作提示

**失败即记录**：任意一项没勾上 → 在观察表记一条，重点写"卡在哪一步、卡了多久"。

---

### Task 2 · 联机全流程，含断线刷新

**时间：10 分钟**

> 这个 Task 需要 **两个人**（你自己 + 一个朋友），或者你自己两台设备/两窗口操作也行——但如果只有你一个人，就记录为"单人自测"，可信度低，注明即可。

#### 给被试的话术（复制发给朋友）

> 我们联机下一盘。
> 我现在建房，会给你一个 6 位房间码，你在自己电脑上输入房间码就能进来。
> 你是白棋，我黑棋，你先等我。
> 规则跟刚才一样。
> 中途我可能会假装网卡、刷新一下页面，你别慌，等着就行，看会不会自己恢复。

#### 执行步骤（观察者按这个走）

1. 被试 A（黑）首页点「创建房间」，拿到 6 位房间码。
2. 把房间码发给被试 B（白），B 首页输入 → 「加入」。
3. **B 加入后，双方各自说一句话确认"我看到棋盘了"**（这一步记录双方等待时长体感）。
4. 正常交替落子 **4 手**。
5. **断线测试（关键）**：其中一方按 F5 刷新页面（模拟断线重连），继续观察：
   - 刷新后是否还在同一个对局里？
   - 轮到谁落子是否显示正确？
   - 刷新后落一子，另一端能不能同步到？
   - 走子记录还在不在？
6. 再走 2–3 手收尾。

#### 要盯的行为点

1. 房间码好不好念/好不好复制（有没有大小写混淆、字符歧义，比如 0/O、1/I）
2. 等待对方时有没有明确文案（"等待对方加入…"），还是空白让人干等
3. 刷新后回到对局：状态恢复是否完整（棋盘 / 回合 / 计分 / 走子记录 / 提示开关状态）
4. 同步延迟体感：一方落子后，另一方**多久**看到
5. 同步延迟有没有造成"我明明下了，怎么还没轮到/怎么已经轮到我了"的误解
6. 刷新后**谁的黑白身份**有没有变（不能变）
7. 非当前回合方点棋盘：有明确禁止提示，而不是静默无效

#### 通过标准（勾选）

- [ ] 房间码一次输入成功，无需重试（大小写不敏感或自动大写）
- [ ] 建房方能看到明确的"等待对方加入"提示
- [ ] 加入后双方**15 秒内**都进入可落子状态
- [ ] 4 手交替落子无卡死，回合提示始终正确
- [ ] **F5 刷新后自动回到原对局，棋盘 / 计分 / 走子记录 / 执子颜色全部一致**
- [ ] 刷新方刷新后落的一手，对方能正常看到（同步没断）
- [ ] 双方计分数字**任何时刻都相同**
- [ ] 落子 → 对方可见的延迟 **≤ 5 秒**（本地 mock；若测线上则记录实际秒数）
- [ ] 非回合方点击棋盘有可见反馈（变灰/提示"等待对方落子"）

**失败即记录**：尤其"刷新后回到对局"是零容忍项，见 `bug-report-template.md` 的 P0 定义。

### Task 3 · AI 难度的主观体感

**时间：8 分钟（只打 简单 和 困难 各一局，中等/大师按有余力补）**

> 注意：实现里 AI 是**四档**——简单 / 中等 / 困难 / 大师（简单=随机，大师=迭代加深+残局精确）。

#### 给被试的话术（复制发给朋友）

> 这回你跟电脑下。你可以选难度，我建议你先选「简单」打一局，打完再选「困难」打一局。
> 打完请你跟我说一句话：这局难不难？难在哪儿？是"找不到该下哪"那种难，还是"下了但被电脑反杀"那种难？
> 边下边说，比如"这步我犹豫了"、"哎我没想到它会下这"。

#### 要盯的行为点

1. 难度选择是否一眼看懂（文案 + 说明是否够）
2. **AI 落子时界面卡不卡**（AI 在 Web Worker 里算，理论上不卡——但这是必须人工确认的手感项）
3. AI 思考有没有**可见的反馈**（有没有"AI 思考中"之类提示，还是干等着）
4. "简单"是不是真的简单（新手能不能赢）
5. "困难/大师"是不是明显更强（会不会赢得太狠、完全没有还手之力）
6. 三四档之间**能不能感知到梯度**（如果简单和困难手感一样，难度设计就有问题）
7. 局末的战绩统计（按难度记录本地战绩）被试有没有注意到
8. 提示开关在 AI 局默认开着——被试有没有因此觉得"这局太简单了"（难度+提示的耦合）

#### 通过标准（勾选）

- [ ] 被试能独立完成"选难度 → 开始"，不需要被告知点哪里
- [ ] AI 落子期间**界面不冻结**（能正常拖动/滚动/点其他按钮，AI 思考超过 1 秒也不卡）
- [ ] 存在明确的"AI 思考中"或类似状态反馈（没有则记为问题：静默等待 = 体感像卡了）
- [ ] 「简单」档被试**至少赢过一局**（新手向）
- [ ] 「困难」或「大师」档被试**至少输过一局**（难度确实生效）
- [ ] 被试能说出简单和困难"感觉不一样"，并能指出差别在**哪**（梯度可感知）
- [ ] 局末胜负结算清晰（比分 + 谁赢 + 可否再来一局）

**加分观察**：「简单 + 开着提示」是否等于送分——如果被试在简单档开着提示也能赢，说明提示在 AI 局提供的信息过强，可作为 P1 反馈给设计侧。

### Task 4 · 一局完整对局到终局

**时间：10 分钟**

> 这是验证"没有边角 bug"的一局。目标不是赢，是**能不能顺利走到终局并看到结算**。

#### 给被试的话术（复制发给朋友）

> 我们认真下一整盘，走到底。
> 中间如果出现"诶我这里好像不能下"、"怎么轮到我了"、"这个数不对"这类情况，**马上停下来告诉我**，别自己将就。
> 终局之后告诉我：比分是多少、谁赢、你想不想再来一局。

#### 执行步骤

1. 双方正常对弈，不刻意赶速度。
2. 中途刻意制造一次**跳过场景**：当一方无合法落子时，观察是否自动跳过并提示对方。
3. 观察**最后一手**落子后：双方是否同时进入终局。
4. 观察终局结算：比分数字、胜负文案、"再来一局"入口。
5. 点「再来一局」，验证能否干净重开（棋盘清空、比分归零、谁先手是否正确重置、回合回到黑棋）。
6. 顺手验证非 AI 局的提示开关能否在局中切换，且切换后立即生效。

#### 通过标准（勾选）

- [ ] 完整走到终局，中途无卡死、无需要刷新才能继续的情况
- [ ] 出现"无合法落子"时，**自动跳过**且双方都看到明确提示
- [ ] 最后一手落下后，双方**都**进入终局（不是只有落子方进入）
- [ ] 终局比分 = 棋盘上实际棋子数（**逐格核对过**）
- [ ] 胜负文案正确（黑胜/白胜/平局 三种都试过至少一次最好）
- [ ] 「再来一局」后棋盘清空、比分归零、**黑棋先手**、提示开关状态按预期（沿用 or 重置，说明清楚即可）
- [ ] 对局页的走子历史栏完整可看（手数与实际一致）
- [ ] 全程无"落子丢子"（落了子但盘面没变 / 刷新后子消失）

**失败即记录**："双方不同步进入终局"、"比分与棋盘不符"、"丢子"属于**零容忍级**，必须开单。

## 3. 试玩后必问的 5 个问题（给被试）

在 `observation-sheet.md` 里有完整版，口语化，直接问：

1. 你觉得这游戏好玩在哪？或者不好玩在哪？
2. 刚开始的时候，你有没有不知道该干嘛的地方？是哪一刻？
3. 跟电脑下和跟人下，你更喜欢哪个？为什么？
4. 界面上有没有哪个地方你看不清 / 不舒服？
5. 刚才那一局，你想再来一局吗？

**第 5 题是最关键的信号**——它比任何满意度打分都准。

---

## 4. 试玩结束后（观察者自己的收尾，5 分钟）

1. 填完 `observation-sheet.md`（每个 Task 一行 + Bug 记录列）。
2. 有 Bug 的，用 `bug-report-template.md` 的格式各开一条。
3. 对照本次四大类缺口，标出哪些是 **P0 零容忍**（落子丢子 / 对局卡死 / 刷新丢对局 / 双方不同步 / 比分算错），这些必须本轮修。
4. 手感类问题（动画观感、AI 卡顿、暗色对比度、提示默认态）**不要自己脑补结论**，只记录被试原话 + 你的观察，这类要靠人工反复看。

## 附：与其他测试的关系

- 本手册是**人工 Playtest**，测的是"好不好玩、会不会用、手感如何"——这些自动化测不了。
- 每次改完代码，先跑 `tests/playtest/smoke-checklist.md`（5 分钟人工冒烟），再决定要不要重约真人试玩。
- 单元测试和 E2E 已覆盖的逻辑（回合流转、双端棋盘一致、房间码校验、终局判定），本手册的 Task 2 / Task 4 会**从用户视角再验一遍**，但两者不互相替代。
